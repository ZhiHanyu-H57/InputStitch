它能做什么What it does

InputStitch 的核心不是“录一段按键再播放”，而是把不同输入和输出放进同一套可并发、可观察的运行系统。

InputStitch is more than recording and replaying keystrokes. It puts different input and output types into one concurrent, observable runtime.

01

键盘、鼠标和手柄互相映射Map keyboard, mouse and controller input

键盘键、鼠标键、侧键、滚轮和 XInput 控件都可以作为触发来源。输出可以是键盘、鼠标，或者 Xbox 360 / DualShock 4 虚拟手柄。

Keys, mouse buttons, side buttons, wheel input and XInput controls can all be triggers. Output can target keyboard, mouse, Xbox 360 or DualShock 4 virtual controllers.

Shift + E → K (held)Mouse 4 → click + wheelRT 80% → virtual stick
02

多个宏可以真正同时运行Run several mappings at the same time

普通时序宏、复杂 Hold 和 Held Mapping 可以并发运行。每次运行都有独立的来源和停止状态，而不是“后启动的宏覆盖前面的宏”。

Timed sequences, advanced Holds and Held Mappings can run concurrently. Each run keeps its own source and stop state instead of replacing whatever started earlier.

Held A ─┐Held B ─┼─ simultaneousSequence ─┘
03

复杂状态可以看见，也可以安全停下Inspect state and stop safely

运行观察会显示当前运行实例、来源、映射层和合并后的输出。普通时序宏支持单步执行；默认紧急停止为 Ctrl + Shift + F12。

Runtime Observation shows active runs, sources, layers and merged output. Ordinary sequences can be stepped through, and the default Emergency Stop is Ctrl + Shift + F12.

从常见操作开始Start with common actions

Quick Create 把最常见的三种需求直接做成模板。创建后仍然可以进入完整编辑器继续调整。

Quick Create covers three common jobs directly. The result can still be edited in the full editor afterwards.

两个宏同时按住 K，谁负责松开？Two macros are holding K. Who releases it?

这是 InputStitch 做 Output Ownership 的原因。每个来源只清理自己的贡献；只要还有另一个来源要求 K 保持按下，最终输出就不会松开。

That is why InputStitch tracks Output Ownership. Each source removes only its own contribution. If another source still owns K, the merged output stays pressed.

  • 数字按键按来源计数，不互相误释放。Digital buttons are reference-counted by source.
  • 扳机和摇杆按明确规则合并到合法范围。Triggers and sticks merge by explicit rules into valid ranges.
  • 真正的全局中和只留给紧急停止。Global neutralization is reserved for Emergency Stop.

映射层、手柄与运行状态Layers, controllers and runtime state

映射层Mapping layers

可以创建任意命名的映射层，并用键盘、鼠标或手柄触发切换。Base 始终有效，同时最多叠加一个当前活动层。

Create named layers and switch them with keyboard, mouse or controller triggers. Base remains eligible while one named layer can be active on top.

手柄输入与虚拟输出Controller input and virtual output

XInput 手柄可以直接触发键鼠或混合宏。需要时创建 Xbox 360 / DualShock 4 虚拟手柄；只做键鼠自动化时可以完全不创建虚拟手柄，也不需要 ViGEmBus。

XInput controllers can trigger keyboard/mouse or mixed macros. Create an Xbox 360 or DualShock 4 virtual controller only when needed; keyboard/mouse-only workflows can skip ViGEmBus entirely.

实验性手柄接管Experimental controller takeover

设备接管已经有事务、健康监测与恢复日志基础，但实体手柄 + HidHide + 真实游戏的完整验收尚未完成，因此仍明确标记为 Experimental。

Controller takeover has transactional setup, health checks and recovery journals, but full physical-controller + HidHide + real-game acceptance is not complete, so it remains explicitly Experimental.
