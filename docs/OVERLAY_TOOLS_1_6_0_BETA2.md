# InputStitch 1.6.0-beta.2 — 录制与断网恢复验收

2026-10-24，本地测试版。正式更新源保持 1.5.2。

补齐上一版的 OBS 游戏捕获、隔离整机断网和真实 IPv6 验收。
66 个生产源码中，64 个未改；另两处仅更新 Beta 版本号和计时器的 OBS／RTSS
兼容设置说明。计时器、网络助手、宏运行及停止代码与 beta.1 相同。
本轮没有新增功能、驱动或随程序分发的依赖。

## 使用

普通置顶计时器保持原操作。录制 RTSS 计时器时，先运行 RTSS 7.3.7+，开启：

1. OBS 游戏捕获属性中的“捕获第三方叠加层”。
2. RTSS Setup 中的“Use Microsoft Detours API hooking”。

默认 RTSS hook 在本机使原生游戏捕获基线冻结，启用上述兼容方式后实录通过。
这一设置也见于 [OBS 官方故障排查](https://obsproject.com/kb/game-capture-troubleshooting)。
验收只临时设置专用测试目标的 profile；测试后已删除，现有游戏配置哈希未变。

其余工具操作见 [beta.1 使用说明](OVERLAY_TOOLS_1_6_0_BETA1.md#使用)。
运行测试版前正常退出当前 InputStitch；两个版本共用用户配置。

## OBS 实录

OBS 32.2.2；原生 x64 D3D9 目标；独立进程运行生产 `TimerController`。
始终使用 `game_capture` 源。4 段约 6 秒的 MKV，共解码检查 48 帧：

| 录制场景 | 结果 |
|---|---|
| 无计时器基线 | 游戏绿块持续运动，帧哈希变化 |
| 第三方叠加层开，RTSS＋普通置顶 | RTSS 入录，普通置顶未入录 |
| 第三方叠加层关，两种计时器均开 | 两种计时器均未入录 |
| 第三方叠加层开，仅普通置顶 | 普通置顶未入录 |

桌面正对照同时检测到两种计时器，排除未显示造成的假阴性。
RTSS 文字单独生成的黄色掩模有 12／12 个不同哈希，证明时间文字持续更新。
OBS 输出跳帧为 0。现有 OBS 的 17 个配置文件哈希不变；便携测试实例及临时
WebSocket 设置均已清理。这个结果覆盖本轮的原生 x64 D3D9 捕获路径。

流程及复验：[OBS 自动验收](OBS_TIMER_ACCEPTANCE.md)。

## 隔离整机与 IPv6

独立 QEMU Windows Server 2022 评估版内核，软件 CPU 仿真；双栈虚拟网卡访问
外部回声端 `10.0.3.2`／`fec1::2`。TCP／UDP 均校验随机内容原样返回。
两个独立程序路径 A／B、真实 WFP 过滤和真实进程终止，**299 项通过**，最终一轮约 99.6 秒。

| 场景 | 阻断和恢复结果 |
|---|---|
| 指定程序 | A 的 IPv4／IPv6 TCP／UDP 新连接及已有流被阻断；B 同时保持连通；恢复后 A 连通 |
| 整机，主动恢复 | A／B 的四类新连接及已有流均被阻断，恢复后均连通 |
| 整机，主进程正常退出 | 同上，退出后均恢复 |
| 整机，强制结束主进程 | 实际 TerminateProcess，未执行正常清理，网络恢复 |
| 整机，强制结束助手 | 实际 TerminateProcess，主进程仍在运行时网络已恢复 |

每种恢复后均检查新 TCP／UDP 和原有 UDP 套接字；TCP 已有连接可能在阻断时
被系统拆除，验收要求能重新建立连接。助手退出也逐项核对。
整机模式只在独立 Windows 来宾内执行，宿主整机阻断次数为 0。
五个断网阶段宿主 HTTPS 均返回 200。本机的设置和设备文件哈希保持不变，
原 InputStitch／RTSS 实例保持运行。

修正了测试环境的双栈参数和探测器启动竞态。虚拟机身份校验改用快速 SMBIOS
读取，与独立 WMI 查询交叉验证；本机拒绝误运行的自检 15 项通过，来宾 14 项通过。
TCG 下的验收程序集先在来宾内部预编译，避免额外的身份校验及即时编译挤占
生产助手的 10 秒握手期限。生产网络源码和期限均未修改。前期冷启动失败证据保留。

流程及复验：[隔离网络自动验收](ISOLATED_NETWORK_ACCEPTANCE.md)。
