# 架构与性能复查：1.6.2-beta.2

日期：2026-11-06。基线：本地 beta.1，`aeaa22a8d94b14b15f6e704feb638b770568e513`。
本轮生产/测试冻结提交：`9a8ea5e25530eb1922fdc10667ceae514d811c6c`。

现有接口足以继续添加输入和输出后端，当前不需要更换界面框架、引入插件框架或重写调度器。
维护上的主要问题仍是 MainForm 同时承担编辑、运行与退出协调。本轮完成原生输入快照和
界面状态通知两处小范围改进，保留宏运行、配置和输入频率。

## 架构检查

基线生产清单包含 67 个源文件、29,200 行。包含 MainForm partial 的 9 个文件合计
11,760 行，其中也包括同文件内的其他类型；这不是 MainForm 类的精确行数。
单个 `InputStitch.cs` 为 8,085 行，MainForm 从第 3,004 行开始。
这些是规模指标，不作为性能问题或必须重构的单独依据。

| 部分 | 当前判断和依据 | 后续处理顺序 |
| --- | --- | --- |
| 输入扩展 | `InputProvider.cs` 的 IGamepadInputProvider 已统一轮询、拓扑版本、状态和边沿；Composite 隔离索引归属，SDL/XInput 共用消费者 | 保留该接口；新设备仍需验证身份、断开释放和来源隔离 |
| 输出扩展 | `VirtualGamepadBackend.cs` 的 IVirtualGamepadBackend 隔离具体驱动；OutputOwnership 统一合并与释放 | 可在此接入后端，按后端要求保留完整控制器状态，不增加上层分支 |
| 分类与生命周期 | `ConcurrentRuntime.cs` 提供唯一能力分类；MacroRunCoordinator 不引用 WinForms，管理运行身份、停止与进度 | 保留单一分类；不在编辑器复制规则 |
| 执行与界面耦合（P1） | MacroWorker、条件判断、编辑暂停、驱动准备、状态通知和退出仍由 MainForm 协调；partial 只拆文件，不能消除依赖 | 下一步按职责提取执行器，明确输入快照、输出所有权、停止信号、暂停状态和进度通知边界；一次迁移一条已测路径 |
| UI 派发（本轮修复） | 阻塞消息处理后，1,000 次 SetStatusSafe 在旧包排入 1,000 个实际 WinForms 回调 | 合并为一个待处理的最新状态；直接 UI 状态和停止提示使更早的待处理通知失效 |
| 状态快照归属（本轮改进） | 旧 SDL 帧是对象和两个数组，原生每次读取创建三项对象；调用者需要理解可变数组的生命周期 | 用独立值帧和 TryGetSnapshot 表达读取成功与失败，统一归一化仍在提供者 |
| 清理失败隔离（本轮修复） | 原生 Shutdown 整段 catch；一处 Close 异常会跳过剩余句柄和 Quit，已故障复现 | 分别尝试每个 Close 和子系统清理，保持重复调用安全 |
| 主窗体退出（P1 后续审查） | MainForm_FormClosing 仍有一段覆盖多个子系统的 try/catch；某个外部清理异常可能跳过后面的步骤 | 后续单独做故障注入，检查网络恢复、停止和最终输入释放是否各自独立完成；本轮未更改该生命周期 |
| 测试可维护性（P2） | 源清单唯一且有漂移检查；影响选择和有效结果复用已经存在。普通结果指纹仍覆盖所有生产源 | 当前继续按影响选择；未来只有在实际出现大量无关重跑时，才收窄单项依赖，避免新增一套脆弱的依赖维护表 |

架构建议中尚未实施的项目不计为本轮修复。特别是 MainForm 的执行职责并未完全解耦，
也没有仅靠新增接口宣称性能提升。当前专用宏工作线程的取消和所有权模型保持不变。

## 已完成的改动

### 原生 SDL 采样

SDL 原始状态改为 16 字节值帧：按钮位和六个轴值。TryGetSnapshot 成功才发布完整帧，
无句柄或不可用时返回 false 和零帧。MapSnapshot 仍是唯一 SDL → 应用状态的映射位置。
未保留第二套旧数组接口；内部调用者和假实现一并更新。

设备成员相同时复用只读的托管快照，成员变化时创建新快照，先前返回的数组不被修改。
每轮原生枚举与释放、每个连接设备的 15 次按钮和 6 次轴读取保持不变。
这遵循 SDL 的[枚举内存归属](https://wiki.libsdl.org/SDL3/SDL_GetGamepads)、
[按钮](https://wiki.libsdl.org/SDL3/SDL_GetGamepadButton)和
[轴值](https://wiki.libsdl.org/SDL3/SDL_GetGamepadAxis)约定；没有通过降低采样率换取数据。

原生清理故障复现：第一次 Close 抛异常时，旧版只尝试 1 次 Close、0 次 Quit，
还剩 1 个记录句柄；修复后尝试 2 次 Close、1 次 Quit，记录清空。这里验证的是尽力清理
顺序和内部生命周期；异常本身不被当作原生资源已经成功关闭的证明。

### 界面状态通知

后台状态生产者只替换最新文本，并共用一个待处理 UI 回调。UI 线程取出文本后才更新控件，
锁内不操作控件、不等待 UI，也不影响宏输出和停止。直接 UI 命令清除旧通知；普通停止和
紧急停止的状态提示也经过这一路径。窗体关闭后的状态更新保持无操作。

本轮只合并状态文字，不合并键鼠输入、输出、停止命令或录制数据。它减少积压，尚未把整个
运行模块从 MainForm 中提取出来。

## 测量

同一驱动、同一主机，原生委托 stub 固定输入，预热 1,000 轮，三次各 200,000 轮，
使用运行时每线程分配计数。stub 的原生列表预先分配，以下不包含真正 SDL/驱动分配。

| 设备数 | beta.1 托管分配 / 样本 | beta.2 | 原中位耗时 | 新中位耗时 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 4,800,000 B | 0 B | 2.839 ms | 3.063 ms |
| 1 | 32,000,000 B | 0 B | 13.949 ms | 13.290 ms |
| 4 | 110,400,000 B | 0 B | 46.721 ms | 45.301 ms |

每个样本仍有 200,000 次 Update/List/Free；连接设备的实时读取次数不变。
局部耗时接近，已确认的收益是减少托管分配，不据此声称整体 CPU 明显下降。

状态通知旧包实测：界面不处理消息时 1,000 次后台写入对应 1,000 个实际回调，
最终 beta.2 成品对应 1 个回调；两者处理后均显示 `status-999`。
这测量的是已经送达程序的状态请求及实际 WinForms 队列，不是物理输入延迟。

## 验证与交付

本轮按差异选测试，窗口检查在不切换的私有桌面进行，宏输出使用隔离观察器。
不反复执行无关长测、OBS 捕获或真实网络中断，不以人工试用作为验收条件。

- 14 套定向回归通过，包括 95 项 SDL、107 项 UI 安全/状态通知、55 项运行协调、
  303,716 项输出所有权、282 项工具集成和 802 项配置/产品检查。
- SDL → MainForm 控制器回调 → 按住映射 → 所有权的 100 次断开/重连流程通过，
  旧来源释放、重连基线、其他来源隔离和 Dispose 清理正常。

  紧急停止提示、关闭及关闭后的更新。实际队列保持一个待处理回调。

  保存状态恢复、消息循环和正常退出。中英文默认/紧凑设置、旧 XML 默认值通过。
