# InputStitch 1.5.1 release verification — 2026-10-22

## Scope and freeze

Stable version `1.5.1`, FileVersion `1.5.1.3`, prerelease `false`.
Runtime/test baseline: `659e7f7defd9f29efa3942852135746259306c19`, with
handoff commit `0bd0504`. The formal-release production delta is ReleaseInfo only;
the other 56 production files retain the final beta.3 hashes. No new feature,
dependency, configuration field or architecture expansion is included.

Acceptance is automated. Another user trial is not a release prerequisite.
Development may continue selecting tests by impact; this formal release runs all
36 regression groups and the separate applicable release checks.

Packaged resource probe, 30 seconds per phase after an advanced-trigger release:

The original 1.4.3 and 1.5.0 synthetic configuration fixtures were generated by
their respective official executables (see `tests/fixtures/README.md`). Actual
isolated editor load/save/reopen compares every original XML leaf. Changed files
must have byte-exact backups; unchanged files must remain byte exact without
redundant backup rotation. The updater also tests fixed names, child-process
wait/restart, executable/configuration backups, shortcut targets, failure rollback
and refusal to overwrite an existing unrelated InputStitch.exe.

An initial formal run stopped in the newly added 1.5.0 fixture check because the
test assumed every save created a backup directory. The file was unchanged;
ConfigStore deliberately avoids a redundant replacement/backup. Corrected the
test expectation to verify exact original preservation or exact backup depending
on whether contents changed. No production behavior changed. This stopped run
does not count as a full pass.

## Evidence limits

- The sustained runtime observer uses isolated output and no forced garbage
  collection. Its actual duration and counters are reported; it is not overnight
  or universal hardware evidence.
- Real SendInput/ViGEm/XInput acceptance is separate from observer-only tests.
  Its host compiles the frozen production sources. Packaged smoke loads the actual
  distributed assembly and verifies embedded dependency/runtime extraction,
  cache repair, startup, saved crosshair restoration and shutdown.
- The prepared-long-press test supplies delivered trigger/focus seams. It verifies
  output before a deliberately blocked UI resumes, not end-to-end physical-hook
  or game latency. Initial device preparation and own-window checks retain UI
  cooperation.
- Windowed/borderless crosshairs retain their accepted scope; exclusive fullscreen
  is not supported. Experimental controller takeover retains separate physical
  device/HidHide/game acceptance.

uses downloaded published assets, checked against GitHub digests, SHA256SUMS and
both update manifests. Recheck startup on those actual published executables.
