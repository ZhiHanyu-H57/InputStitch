# 长按触发与界面阻塞隔离 — 1.5.1-beta.3

2026-10-22，本地 `perf/runtime-coordination` 分支；不新增功能、不推送发布，
Stable 1.5.0 的 main、tag、latest 和更新镜像保持原状。正式发布仍须全套验收。

## 实施范围

- 有效按下边沿接受后，为 LongPress 准备独立宏/条件/触发快照。
  复用已有 10 ms 输入线程判断阈值，复用协调器与工作线程启动。
  输出设备已就绪且目标在本工具以外时，计时与启动均不等待 UI 消息。
- 首次连接虚拟手柄、驱动提示、本工具前台的计时/窗口条件/编辑检查仍由 UI 处理。
  UI 请求合并；驱动连接和弹窗在启动凭据锁之外，返回后重新验证。
  焦点切换到本工具时，后台读取自己的窗口标题会直接按无有效条件信息处理，
  避免同步等待阻塞的 UI；UI 自己读取仍可用。
- 长按启动凭据只能消费一次。松键、重新按下、定义修改、所选/全部停止、
  录制/捕获/弹窗/编辑保护、条件丢失和禁用均可阻止不再有效的启动。
  全部停止先清理触发凭据，再停止协调器；收到紧急停止事件时同步停止工作宏，
  原有 UI 紧急清理继续处理其他来源、路由和恢复。
- 后台启动的长按宏在风险 UI 保护启用、且本工具回到前台时先暂停并释放其来源，
  离开后恢复；已有 UI 编辑保护也继续生效。普通界面启动保留原保护顺序。
  这项保守保护不依赖卡顿中的控件焦点通知。
- 没有新增运行库、常驻线程、计时器或配置字段；松键后不保留运行快照。
  其他高级触发及原 Toggle/Hold 保持原路径。本轮未迁移键鼠钩子注册/捕获界面，
  也未重写执行器或输出所有权。生产清单/csproj 为 57 个源文件。

## 延迟与真实输出

同一输入接缝 → 生产输入调度 → 实际工作宏 → 隔离观察器：
阈值 150 ms、界面阻塞 400 ms，上一测试版记录为 405 ms；本版单次
152 ms，8 次样本为 [254, 151, 151, 152, 152, 153, 152, 152] ms，
中位 152 ms，均在 UI 恢复前产生输出。首轮冷启动样本包含 JIT 等成本。

Input Lab 新增实际 ViGEm/XInput 场景：UI 不处理消息期间，独立读取 XInput，
150 ms 阈值在约 178 ms 读到 A 按下，400 ms UI 阻塞尚未结束；停止后释放正确。
全部真实输出 **81 项通过、0 失败**，也覆盖原 SendInput 键鼠、并发、按住映射和紧急停止。
这一长按场景使用显式输入/物理状态/焦点接缝，输出是真实设备报告。
不把这些数字等同于首个实体键事件、系统钩子投递或具体游戏的总输入延迟。
