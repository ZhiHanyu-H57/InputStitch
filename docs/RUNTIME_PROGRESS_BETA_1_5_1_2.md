# 1.5.1-beta.2：运行进度、单步命令与诊断开销

日期：2026-10-22。接续已验收的 beta.1（`1f673aa`），维持 1.5.0 的宏执行、
所有权、设备后端、配置和界面布局。仅交付本地测试版，未发布或替换 Stable。

## 解耦边界

`MacroRunCoordinator` 继续接管执行进度的开始、循环、步骤、单步等待、
下一步命令及诊断用按住状态。MainForm 不再直接写这些进度字段或设置单步信号；
工作线程调用协调命令，按钮读取一次性捕获的 `MacroRunControls` 值。

诊断界面读取脱离运行对象的 `MacroRunProgressSnapshot`，按住输入有独立副本，
界面格式化或修改这些副本不影响执行线程。RunId、SourceId、停止、结束与进度
采用原来的同一运行锁。迟到的进度不能覆盖 stopping，旧任务不能污染重新启动的任务。

步骤执行、输出所有权、时序等待和界面安全暂停仍沿用现有实现；没有引入新定时器、
线程模型、框架或运行库。执行核心与条件输入仍有 MainForm 依赖，尚未完全解耦。

## 移除每次按键边沿的诊断文字处理

旧版本每次同步按住状态，除了复制输入，还逐项查询显示名称、分配名称列表、
数组并拼接字符串。后台运行期间即使没有查看诊断，也支付这项成本。

现在继续保留安全的原始输入复制，文字仅在用户查看运行观察/诊断时生成，
在获取进度快照后释放运行锁再格式化，避免名称查询阻塞宏的进度同步。
输出路径没有删去按下/松开、释放或所有权操作，也没有降低手柄轮询节奏。

`tests/Run-RuntimeProgressProbe.ps1` 加载指定的真实 EXE，隔离应用路径，
只调用生产的状态同步路径；不安装钩子、不启用输入轮询、不运行宏、不输出系统输入，
不强制 GC。暖机 1,000 组，随后每次交替发布 8 个按住输入/空状态，共 200,000 次，重复 3 次。
这是一段生产路径的微基准，不是整机 CPU、游戏帧率或完整宏吞吐量测试。

| 样本 | beta.1 耗时 ms / Gen0 | beta.2 耗时 ms / Gen0 |
|---|---:|---:|
| 1 | 2387.88 / 64 | 114.19 / 7 |
| 2 | 2205.39 / 63 | 101.25 / 6 |
| 3 | 2347.42 / 64 | 74.52 / 6 |

最终成品中位耗时 2347.42 → 101.25 ms，约减少 95.7%；Gen0 中位数 64 → 6。
不能把这项局部收益表述为整个宏工具 CPU 降低 95.7%。

x64 EXE 1,988,608 B，x86 1,819,136 B，分别比 beta.1 增加 1,536 / 2,048 B；
相对正式版 1.5.0 增加 2,048 / 2,560 B。没有新增依赖；原生 SDL3 缓存大小未变。

## UI 阻塞的触发延迟证据

集成测试从合成输入事件进入正式触发入口，经 10 ms 生产调度器、UI 派发、
真实宏工作线程到隔离观察后端。长按阈值 150 ms：最终源码的正常 UI 样本 187 ms；
UI 阻塞 400 ms 的样本 405 ms。没有物理钩子或真实游戏输入，不能当作设备延迟。

结果确认高级触发仍受 UI 派发影响；本轮不宣称解决这项延迟，也没有绕过
UI 安全复查直接启动宏。后续应先整理可在线程间安全读取的条件输入和提交边界，
再评估纯决策迁移。当前职责提取和后台诊断减负独立成立。

## 按影响选择验收

本轮选择 13 组：SourceManifest、MacroRunCoordinator、InputPipelineIntegration、
UiSafety、OutputOwnership、MacroWorkerPool、MacroTiming、ModifierSafetyPolicy、
Layer、LayerContext、Productivity、ReleasePolicy、ActivatorCondition。
新增进度/副本/单步/迟到更新覆盖；实际运行时的中英文诊断文字仍有集成检查。
布局、网络更新、设备提供者和驱动未改动，不重跑它们的完整矩阵。
正式发布仍执行全部 35 组与完整发布门禁，本轮不声明全套通过。

成品启动、创建到运行、实际输出、资源采样与持续运行的最终结果随交付记录提供。
