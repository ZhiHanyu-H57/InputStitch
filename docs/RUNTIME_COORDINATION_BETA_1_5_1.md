# 1.5.1-beta.1：运行协调与后台开销

日期：2026-10-22。基线为已发布的 1.5.0（`166faab`），本轮仅交付本地测试版。
不新增产品功能、依赖或驱动；不更新 GitHub latest、Stable 清单或下载镜像。

## 本轮边界

`MacroRunCoordinator` 集中管理运行登记、宏到 RunId 的索引、单步入口检查、独立停止、
停止全部、最终移除和停止原因。模块不引用 Form、界面派发、输出后端或定时器，
停止追踪回调由外部提供，因此生命周期可以脱离窗口单独验证。

MainForm 通过协调模块发起这些操作，界面和诊断不再直接修改运行索引。
继续共享原有运行锁，使按住映射、界面安全暂停和执行线程看到的状态保持一致；
结束原因在同一锁内选择，旧任务的停止/结束不会删除或停止后来重新启动的任务。
热路径枚举仍返回字典的原生 ValueCollection，避免接口枚举造成额外分配。

这是按职责逐步提取的第一步。步骤执行、部分运行进度和条件/UI 安全检查仍在 MainForm，
未宣称完全解耦，也未把 UI 相关检查移到输入线程。计时、输出所有权、线程复用和 XML
结构沿用 1.5.0。下一步仍应先测量 UI 阻塞时的触发延迟，再决定纯决策与界面的边界。

## 消除一次使用后的空闲检查

旧实现以“保存了高级触发历史”判断是否需要周期检查。高级触发用过一次，松键后仍保留
历史状态，因此输入线程每 10 ms 继续向 UI 派发空检查，直到编辑/重置清除状态。

现在单独计数仍处于按下状态的触发，松键后暂停周期派发，双击历史保留；长按、短按超时、
按住期间的条件变化继续按原节奏检查。重复 KeyDown/KeyUp、多个同时按住的触发、滚轮、
重置和清空均有定向覆盖。没有改变已连接手柄的轮询节奏或提高系统全局计时精度。

## 测量方法与结果记录

`Run-ResourceProbe.ps1 -AfterAdvancedTrigger` 对真实 EXE 在内存中模拟一组高级触发边沿，
不发送系统输入。首先请求并排空 1,000 次周期检查，记录实际进入 UI 队列的次数，
然后暖机 5 秒，准星关/开各测约 30 秒。宏禁用、应用路径隔离、不创建虚拟手柄、
不强制 GC。CPU 百分比以一个逻辑核心为 100%，不能当作整机占用。

同机顺序对照，16 个逻辑处理器、0 个可见控制器来源；高级触发松键后：

| 样本 | 1.5.0 | 1.5.1-beta.1 |
|---|---:|---:|
| 1,000 次周期请求进入 UI 队列 | 1,000 | 0 |
| 准星关闭，约 30 秒 CPU（单核心） | 4.480% | 2.969% |
| 准星开启，约 30 秒 CPU（单核心） | 3.751% | 2.918% |
| 准星关闭，期末私有内存 | 41,103,360 B | 38,993,920 B |
| 准星开启，期末私有内存 | 41,025,536 B | 38,912,000 B |
| x64 单文件 EXE | 1,986,560 B | 1,987,072 B |
| x86 单文件 EXE | 1,816,576 B | 1,817,088 B |

CPU 样本下降约 22%–34%，仅代表此次同机、无设备、高级触发已松开的观察，
不是所有配置或硬件的固定收益。未使用高级触发的启动空闲路径原本就会跳过此检查。
包体仅增加 512 B/架构，无新增运行库；SDL3 缓存大小未变化。

完整数值和最终文件哈希随本地交付记录提供。首次资源样本与其他测试有重叠，
不作前后对照；锁内结束原因修正前中断的持续运行也不计作通过。
只使用最终源码的持续运行与顺序执行的成品资源对照作为验收。
