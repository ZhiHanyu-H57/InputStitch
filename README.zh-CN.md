# InputStitch

[English](README.md) | [简体中文](README.zh-CN.md)

**InputStitch —— Windows 输入映射与宏工具**

InputStitch 可以把键盘、鼠标和手柄组合成你需要的输入方式：按一下、按住、循环、顺序执行，或者用一个输入去触发另一组输入。它尤其适合需要精确时序、多个输入同时存在、以及随时能够安全停止的场景。

界面支持简体中文和 English 即时切换。程序仅支持 Windows。

## 现在能做什么

### 键盘与鼠标宏

- 录制或手动编辑键盘、鼠标按键、侧键和滚轮操作。
- 为每一步设置按住时间和下一步之前的等待时间。
- 支持固定次数、无限循环、按一次启动/停止、按住运行/松开停止。
- 支持修饰键组合，例如 `Shift+E`、`Ctrl+F`。
- 可以同时运行多个不同的宏；一个宏停止时不会把其他宏正在保持的输入一起释放。
- 普通时序宏支持“单步执行 / 下一步”，方便调试。
- 步骤支持撤销和重做。

### 虚拟手柄输出

在“设置 → 输入与安全 → 虚拟手柄输出”的手柄类型下拉菜单中，可以选择：

- `Xbox 360`；
- `PS4 / DualShock 4`；
- **不创建虚拟手柄（仅使用键盘/鼠标功能）**。

选择“不创建虚拟手柄”后，InputStitch 启动时不会因为配置里存在手柄输出宏而创建 ViGEm 虚拟设备；键盘/鼠标宏以及“用实体/其他 XInput 手柄触发键盘鼠标宏”仍然可以正常使用。真正执行虚拟手柄输出宏、手柄汇总、闲置自动手柄输入或手柄接管时，需要先改回 Xbox 360 或 PS4 / DualShock 4；其中手柄汇总/接管会使用 Xbox 360。

选择创建虚拟手柄时，InputStitch 可以输出：

- 正面按键、方向键、肩键、菜单键、摇杆按下；
- 左右摇杆，方向和力度均可调；
- 左右模拟扳机，力度 0%～100%。

编辑时会显示动态手柄预览。预览本身不会发送输入。

### 用实体或其他虚拟手柄触发宏（v1.3.1-beta.1）

测试版开始把 Windows 能看到的 Xbox 兼容手柄正式作为 InputStitch 的输入来源。

你可以直接录制这样的触发方式：

- 手柄 A → 执行键盘 K；
- 手柄 LB → 鼠标左键；
- 手柄 RT → 一段键盘、鼠标和虚拟手柄混合操作；
- 某个手柄按键按住时持续执行一个按住宏。

配置时默认表示“任意手柄上的这个按键”。真正启动一个按住宏后，InputStitch 会记住**是哪一个手柄启动了它**；另一只手柄松开同名按键不会把它错误停止。

左右扳机也能作为触发方式。为避免临界位置抖动，当前采用“达到约 80% 算按下、回落到约 70% 算松开”的判断。

### 把多个手柄汇总到一个虚拟手柄（v1.3.1-beta.1）

在“设置 → 输入与安全 → 虚拟手柄输出”中，可以开启：

**“把其他 XInput 手柄的操作汇总到 InputStitch 虚拟手柄（测试）”**

开启后，InputStitch 会持续读取其他可见手柄的：

- 按键；
- 方向键；
- 左右摇杆；
- 左右扳机；

然后把它们合并到 InputStitch 自己的 Xbox 360 虚拟手柄中。

多个手柄同时操作时不会简单地“最后一个覆盖前面所有人”：按键可以共同保持，扳机保留更大的力度，摇杆按既有的合并规则计算。某一只手柄回中、松开或断开时，只删除这一只手柄自己的贡献，不会把其他手柄或正在运行的宏一起清空。

#### 一个很重要的槽位限制

Windows 的 Xbox 兼容手柄接口通常用 0、1、2、3 四个槽位表示最多四个手柄。

如果 InputStitch 自己创建的虚拟 Xbox 手柄位于 **0 号槽位**，而一个游戏只读取 0 号槽位，那么 1、2、3 号手柄经过 InputStitch 汇总后，就可以通过这个 0 号虚拟手柄送给游戏。

如果 InputStitch 自己的虚拟手柄位于 **1、2 或 3 号槽位**：

- InputStitch **仍然能读取其他手柄**；
- 手柄触发键盘/鼠标宏仍然可以工作；
- 手柄之间的汇总逻辑也仍然会工作；
- 但只读取 0 号槽位的游戏，可能完全看不到 InputStitch 位于后面槽位的虚拟手柄输出。

因此，**“InputStitch 能读取手柄”与“游戏一定能收到汇总后的虚拟手柄”是两件不同的事。**

当前测试版已经加入实验性的**手柄接管**。只有你主动进入“工具 → 手柄接管（实验）”并选择设备后，程序才会尝试改变设备状态：

- 如果 InputStitch 已经在 0 号槽位，只会短暂断开/重连自己的虚拟手柄，用来确认哪些设备是自己、哪些是真正的外部手柄；
- 如果 InputStitch 在 1、2 或 3 号槽位，会先停止正在受管的手柄输出，临时让所有当前外部 XInput/XUSB 手柄离开枚举，再让 InputStitch 自己先重新连接并**硬验证已经成为 0 号**；
- 之后立即恢复所有外部手柄，并再次确认 InputStitch 仍然是 0 号、原手柄也都重新可读；
- **只有上述检查全部通过后**，才会进入 HidHide 隐藏阶段，而且最终只隐藏你明确选择的设备。未选择的外部手柄可能为了取得 0 号而被短暂重新枚举，但不会被 InputStitch 长期隐藏；
- 任一步失败都会终止接管并尝试恢复原状态，不会先把原 0 号手柄藏掉再“赌”虚拟手柄能不能变成 0 号。

当前 XInput 后端最多允许 **InputStitch 1 个 + 外部 XInput 手柄 3 个**同时可路由；超过这个范围会在修改设备前拒绝接管。真正把原设备对普通程序隐藏仍依赖用户自行安装的 HidHide。本功能已经通过自动事务/回滚测试，并在本机用 4 个中立 ViGEm 测试手柄验证了“外部 0/1/2 + InputStitch 3 → InputStitch 0 + 外部 1/2/3”的真实槽位重排顺序；但**实体手柄 + HidHide + 实际游戏的完整接管仍需要真实硬件验收**。

`beta.2` 又增加了**接管运行自检**。接管已经启动以后，InputStitch 会在后台持续检查：自己的虚拟 Xbox 是否仍在 0 号、手柄汇总是否仍就绪、原 XInput 来源是否仍可读、HidHide 总开关是否仍开启、所选原设备是否仍被隐藏，以及 InputStitch 自己是否仍在 HidHide 白名单。一次瞬时异常不会立刻退出；连续两次异常才确认失效。确认失效后会自动尝试恢复 HidHide 状态、停止手柄汇总并清理受管输出，避免原手柄恢复后又同时收到一份汇总输入。

### 映射层（v1.3.1-beta.2）

映射层可以理解成“同一套输入里可以随时切换的另一组规则”。

现在的模型是：

- **基础层**：始终有效；
- **自定义映射层**：可以创建任意多个，并给每个层起自己的名字；
- 运行时一次只激活一个额外层，所以当前有效集合始终是“基础层 + 当前活动层”。

点“**管理映射层…**”可以新增、重命名或删除层。删除一个层时，其中的宏会自动移回基础层；如果删掉的正是当前活动层，会先安全切回“仅基础层”。

每一个宏都可以选择属于哪一层，包括：

- 普通时序宏；
- 按一次启动/停止的宏；
- 复杂的按住运行宏；
- 轻量的持续按住映射。

每个层（包括基础层）都可以录制自己的**切换快捷键**。快捷键可以来自键盘、鼠标或手柄。基础层的快捷键表示“回到仅基础层”。

切换映射层时，旧层里仍在运行的宏会停止，并只释放旧层自己的输出。基础层继续保留。

如果你切到一个新层时，那个层的触发键本来就已经按着，InputStitch 不会因为按键自动重复或手柄轮询而突然启动它；必须先松开，再重新按下。这是为了避免切层瞬间出现意外输入。

当前激活的映射层只是运行时状态，重启程序后重新回到“仅基础层”。新版还修复了一个配置问题：用户删除旧的“映射层 1”后，保存并重新启动时它不会再被默认配置偷偷创建回来。真正的旧配置如果从来没有 Layer 数据，则仍会自动兼容成“基础层 + 映射层 1”。

## 快速开始

1. 下载与你的 Windows 架构匹配的 EXE。
2. 启动 InputStitch，新建或选择一个宏。
3. 手动添加步骤，或者使用“录制宏”。
4. 录制触发方式，并选择“按一次启动/停止”或“按住运行、松开停止”。
5. 如需手柄输出，在设置中选择 Xbox 360 或 PS4 / DualShock 4 并检测连接；如果只用键鼠宏/手柄触发，可以选择“不创建虚拟手柄”。
6. 如需手柄汇总，在设置中开启对应测试选项，并检查 InputStitch 显示的虚拟 Xbox 手柄槽位。
7. 如需映射层，为宏选择所属层；可用“管理映射层…”新增/命名/删除层，并为每个层录制快捷切换方式。
8. 正式使用前先确认紧急停止键能够正常工作。

## 多个宏同时运行时怎么合并

InputStitch 会记录“哪个宏或手柄正在要求哪个输出”，而不是让后启动的宏粗暴地接管整个键盘、鼠标或手柄。

因此：

- 两个宏都要求按住同一个按键时，其中一个结束不会提前把按键松开；
- 多个来源同时要求一个扳机时，采用更大的力度；
- 多个来源同时控制摇杆时，会合并方向并限制在正常摇杆范围内；
- 方向键上下或左右同时出现时，对向方向相互抵消；
- 紧急停止仍然是全局最高优先级，会一次释放全部受管输入。

“工具 → 运行观察”可以查看当前有哪些运行实例、哪些输出正在被保持，以及最终合并后的状态。这里保留了一些面向调试的技术信息，但普通使用不需要理解这些内部名称。

## 虚拟键盘与手柄编辑

“录制触发键”和“捕获输入”旁的下拉箭头可以打开全尺寸虚拟键盘。支持普通键、功能键、数字小键盘、左右 Shift/Ctrl/Alt/Win、Esc 以及“修饰键 + 主键”的组合。

手柄摇杆在编辑器中采用方向和力度：

- `0°`：向前；
- `90°`：向右；
- `-90°`：向左；
- `±180°`：向后。

旧配置中的摇杆 X/Y 数值仍可兼容读取。

## 闲置自动手柄输入

在“设置 → 自动化 → 闲置自动手柄输入”中，可以在一段时间没有操作后发送一次很短的手柄动作。此功能默认关闭，默认参数为 **120 秒、左摇杆向下、150 ms**。

它可以单独锁定一个“挂机目标”窗口：

- 只有目标程序前台时的键鼠操作才重新计时；
- 在浏览器或聊天软件里操作不会拖延目标程序的挂机动作；
- 如果目标程序不存在，闲置输出完全暂停；
- 目标重新出现后，会从完整空闲时间重新计时；
- 实体手柄活动、宏运行和编辑操作也会影响闲置计时；
- 紧急停止会关闭闲置自动输入，需要手动重新开启。

## 虚拟手柄驱动

键盘和鼠标输出不需要额外驱动。如果你只使用键鼠宏，或者只把实体/其他 XInput 手柄当作触发来源，并在设置中选择“不创建虚拟手柄”，也不需要为了这些功能创建 ViGEm 虚拟手柄。

虚拟手柄输出、手柄汇总、闲置自动手柄输入和手柄接管依赖 **ViGEmBus**。它是 InputStitch 用来在 Windows 中创建虚拟 Xbox/PS4 手柄的第三方驱动。上游项目已经停止维护，因此 InputStitch 不会静默安装它；缺少驱动时只会说明原因，并询问是否打开原作者的官方 GitHub Release 页面：

[ViGEmBus 官方发布页面](https://github.com/nefarius/ViGEmBus/releases/latest)

安装后请重启 InputStitch。对于只在启动游戏时识别手柄的游戏，建议先连接 InputStitch 虚拟手柄，再启动游戏。

## 安全提示

InputStitch 会向 Windows 发送模拟的键盘、鼠标和可选虚拟手柄输入。正式使用新宏前，先在无关紧要的程序中测试。

- 设置一个容易按到的紧急停止键，并实际测试一次。
- 不要运行未经检查的宏，不要导入来源不可信的宏包。
- 不要在违反软件、服务、游戏、单位规定或当地法律的场景中使用自动化。
- 在线游戏或受保护程序可能禁止自动化或拒绝模拟输入，兼容性不作保证。
- 其他手柄工具可能占用虚拟设备或手柄槽位。如果游戏识别错手柄，关闭相互竞争的工具、先连接 InputStitch，再启动游戏通常更可靠。
- InputStitch 不会绕过反作弊、访问控制或程序安全机制。

安全问题报告方式见 [SECURITY.md](SECURITY.md)。

## 数据与隐私

## 技术说明与开发计划

普通使用不需要阅读这一部分。

- Windows 的 Xbox 兼容手柄输入使用 **XInput** 接口；它最多暴露 4 个用户槽位。
- InputStitch 的虚拟 Xbox/PS4 手柄由 **ViGEmBus** 提供。
- v1.3.1-beta.1 已完成“读取其他手柄 → 统一处理 → 汇总到自身虚拟 Xbox 手柄”，并加入可恢复的 0 号槽位取得与 HidHide 接管事务。
- v1.3.1-beta.2 又加入接管运行自检和自动脱离恢复；当前代码链已经覆盖“取得 0 号 → 隐藏 → 持续监控 → 异常恢复”。但这台开发机没有实体测试手柄和 HidHide，所以“实体原手柄 + HidHide + 实际游戏”的最终硬件验收仍未完成。
- 更详细的内部设计见 [手柄输入与路由设计](docs/GAMEPAD_INPUT_ROUTING.md) 和 [映射层设计](docs/LAYER_DESIGN.md)。这些文档面向开发者，因此会使用更多英文 API 和内部类型名。

开发计划见 [ROADMAP.md](ROADMAP.md)。
